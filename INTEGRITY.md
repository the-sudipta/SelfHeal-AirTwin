# Integrity: how to check that nothing was changed

## What this can and cannot promise

Nothing can stop the author from adding new commits to this repository. What the measures below do is make every change **visible**: any rewrite of history, or any swap of data, results or images, can be detected by anyone, without trusting the author.

## 1. Signed commits and tags

Every commit and every release tag on `main` is signed with the author's SSH signing key. On GitHub, each commit shows a green **Verified** badge, and vigilant mode is on, so an unsigned commit pushed under the author's name is flagged as **Unverified**.

Check signatures locally against the public keys GitHub publishes for the author:

```bash
curl -s https://api.github.com/users/the-sudipta/ssh_signing_keys \
  | python3 -c "import sys,json; [print('*', k['key']) for k in json.load(sys.stdin)]" > allowed_signers
git -c gpg.ssh.allowedSignersFile=allowed_signers log --show-signature
git -c gpg.ssh.allowedSignersFile=allowed_signers tag -v v0.1.0
```

Each commit must print `Good "git" signature`.

## 2. Protected `main` branch

A branch ruleset on `main` blocks force pushes and deletion, requires signed commits, requires linear history and requires the CI check to pass. The bypass list is empty, so the rules apply to the author as well.

## 3. History is never rewritten

Published commits are never amended, rebased, reset or force-pushed. Mistakes are fixed with a new commit, so the full history of every result stays visible. A clone made at any time remains a prefix of every later clone; if it does not, history was rewritten.

```bash
git merge-base --is-ancestor <old-commit> origin/main && echo "history intact"
```

## 4. Pinned CI

CI runs on every push. Every GitHub Action is pinned to a full commit SHA, so a moved tag upstream cannot silently change what runs.

## 5. Data checksums

The SHA-256 of both dataset archives, exactly as served by the UCI Machine Learning Repository, are pinned in [`data/checksums.sha256`](data/checksums.sha256). `airtwin download` refuses any archive that does not match, the image build stops on a mismatch, and `airtwin check` re-checks the archives inside the container.

## 6. Results that anyone can regenerate

`docker compose run --rm twin reproduce` reruns every experiment and compares each regenerated table with the committed reference tables in `results/reference/full/`, value by value (absolute tolerance 10⁻⁶). It prints `PASS` or every difference. CI runs a seeded slice of it on every push.

## 7. Release images, provenance, SBOM and checksums

For every signed tag, the `Release` workflow builds the image from the tagged code, pushes it to GitHub Container Registry, records a signed build-provenance attestation, describes the image with an SPDX software bill of materials, reruns **every** experiment inside the released image on GitHub's runner and stops unless `verify` prints `PASS`. It then attaches to the GitHub Release:

| Asset | Content |
|---|---|
| `IMAGE_DIGEST.txt` | The image reference by digest, `ghcr.io/the-sudipta/selfheal-airtwin@sha256:…` |
| `sbom.spdx.json` | Software bill of materials of that image |
| `results.tar.gz` | Tables, statistics, figures, throughput and the web-twin replay regenerated by the release run |
| `SHA256SUMS` | SHA-256 of the dataset archives, of every file in `results.tar.gz` and of the three assets above |

Pull by digest, never by tag, and check where the image came from:

```bash
docker pull ghcr.io/the-sudipta/selfheal-airtwin@sha256:<digest from IMAGE_DIGEST.txt>
gh attestation verify oci://ghcr.io/the-sudipta/selfheal-airtwin@sha256:<digest> --owner the-sudipta
```

Check the release files and the results inside the archive:

```bash
sha256sum --check --ignore-missing SHA256SUMS
tar -xzf results.tar.gz && sha256sum --check --ignore-missing SHA256SUMS
```

The attestation names the workflow, the commit and the tag that built the image, so an image built anywhere else fails the check.

## 8. Independent archives

Release v1.0.0 is archived on Zenodo with the DOI [10.5281/zenodo.23839854](https://doi.org/10.5281/zenodo.23839854): an immutable copy of the source tree of the tag, uploaded as `git archive` of `v1.0.0`. Compare it with the same tag from this repository; any difference shows a change after release:

```bash
git archive --format=zip --prefix=SelfHeal-AirTwin-1.0.0/ -o mine.zip v1.0.0
unzip -q mine.zip -d mine && unzip -q SelfHeal-AirTwin-1.0.0.zip -d zenodo && diff -r mine zenodo && echo identical
```

The repository is also submitted to Software Heritage, which archives every public commit independently; its SWHID appears as a badge in the README.
