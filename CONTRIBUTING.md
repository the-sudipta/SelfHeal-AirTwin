# Contributing

Thank you for your interest in SelfHeal-AirTwin. This project backs a research paper, so every change must keep results reproducible and history verifiable.

## Ground rules

- **One feature per commit.** A feature is one module with its tests, or one config or documentation unit. Do not mix unrelated changes.
- **Signed commits only.** Every commit and tag on `main` must be signed (SSH or GPG) and show "Verified" on GitHub.
- **Never rewrite published history.** No amend, rebase, reset or force push on anything already pushed; fix mistakes with a new commit.
- **No data or generated results in Git.** Data is fetched and checksum-verified at build time; results are regenerated by `reproduce`.
- **Numbers come only from code.** Never hand-edit a result table or figure.

## Development setup (Windows PowerShell)

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install --require-hashes -r requirements.lock
```

On Linux or macOS use `python3.11 -m venv .venv` and `source .venv/bin/activate`.

## Checks before every commit

```powershell
ruff check .
ruff format --check .
mypy src
pytest -q
```

All four must pass. CI runs the same checks on every push.

## Commit messages

Title format: `<emoji> <Type> : <title in imperative first person singular>`, for example `✨ Feat : I add the drift detector module`.

| Emoji | Type | When |
|---|---|---|
| 🎉 | Init | first commit / scaffolding |
| ✨ | Feat | new feature or module |
| 🐛 | Fix | bug fix |
| ♻️ | Refactor | code change without behaviour change |
| ✅ | Test | add or change tests |
| 📝 | Docs | README files, docstrings, CHANGELOG, CITATION, INTEGRITY |
| 🔧 | Config | config, tooling, .gitignore, pyproject |
| 📦 | Build | dependencies, Dockerfile, docker-compose |
| 👷 | CI | GitHub Actions workflows, dependabot |
| 🔒 | Security | signing, checksums, integrity checks |
| 🎨 | UI | web twin, site, README visuals |
| ⚡ | Perf | performance improvement |
| 📊 | Experiment | experiment code, results tables, figures |
| 🔖 | Release | version bump and release notes |
| 🔥 | Remove | delete code or files |

The body explains **What** changed (files and functions), **Why** it was needed and **How** it works. Do not add trailer lines.

## Code style

- Python 3.11, type hints everywhere, a short docstring on every module, class and public function.
- One feature per file; modules talk through small typed interfaces; no circular imports and no global mutable state.
- All tunable values live in `configs/default.yaml`, not in code.

## Dependencies

Edit `requirements.in`, then regenerate the lock file with hashes for Python 3.11 on Linux (the image and CI platform):

```powershell
docker run --rm -v "${PWD}:/w" -w /w python:3.11-slim sh -c "pip install -q pip-tools && pip-compile --generate-hashes --allow-unsafe -o requirements.lock requirements.in"
```
