Big data · digital twin · urban air quality

Sensors drift. The twin notices, heals the data and tells the city which sensor to fix.

SelfHeal-AirTwin is a self-healing digital twin for low-cost air-quality sensor networks. It streams every hourly reading, predicts what each sensor should read, detects drift, corrects it online and closes the loop with a ranked maintenance list.

Open the twin replay Run it with Docker

The problem

Cities fill the gaps between a few expensive reference stations with many low-cost air-quality sensors. These sensors drift: their readings slowly move away from the truth, and nobody notices until decisions have already been made on wrong numbers. Existing big-data air-quality work forecasts pollution well but assumes the sensor data is correct.

A drift-aware twin per sensor

A virtual entity predicts the value each sensor should read from neighbouring sensors, weather and the reference analyzer, and turns the residual into a smoothed drift score (EWMA and CUSUM).

Self-healing in the stream

Once drift is confirmed, the twin estimates an offset and gain correction online and publishes corrected values, but only when the correction is large, clearly better and points the right way.

Feedback to the physical network

A ranked maintenance list says which sensor to recalibrate first and why; a what-if shows how the error grows if it is left alone. This closed loop makes it a digital twin, not a digital shadow.

Why it matters: air-quality alerts, traffic restrictions and health advice are only as good as the sensor data behind them. Catching and correcting drift automatically keeps low-cost networks trustworthy at a fraction of the cost of constant manual calibration.

How it works

Big data, all five V's

VIn SelfHeal-AirTwin
Volume420,768 hourly rows from 12 Beijing sites over four years, plus a year of UCI Air Quality; 370 seeded experiment runs
VelocityEvery reading streamed hour by hour through Apache Kafka and Spark Structured Streaming (or an in-memory replay) into the twin
VarietyTwo datasets: neighbouring sites' readings, weather, low-cost sensor responses and a certified reference analyzer, combined in each sensor's expected value
VeracityThe main goal: detect drifting sensors and correct their data while it streams
ValueA ranked maintenance list, corrected published values and a what-if of the error if a sensor is not visited

Reproduce and verify

One command

docker compose up
docker compose run --rm twin reproduce

The image downloads both datasets during the build, checks their SHA-256 and runs offline. reproduce reruns every experiment and ends with PASS when each table matches the committed reference within 10−6.

Every change is visible

Signed commits and tags, no rewritten history, actions pinned by commit, release images with build-provenance attestations and an SBOM, and SHA-256 sums for data, tables and figures. How to check each one: INTEGRITY.md.
